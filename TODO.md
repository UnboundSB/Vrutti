# Vrutti IDE — Root TODO

**Scope:** `vrutti_ide/` only. Parent `vrutti/` (upstream VS Code source) is never touched.

## Purpose
Root of the Vrutti IDE workspace. Contains build configuration, release packaging, product config, and architectural docs.

## Directory Inventory
| Dir | Purpose |
|-----|---------|
| `src/` | All source code (C++ core, Node ext host, Lit frontend) |
| `bin/` | Ripgrep binary and other native tools |
| `logos/` | Branding assets |
| `installer/` | Inno Setup / PowerShell packaging scripts |
| `scripts/` | Build and release helper scripts (NEW) |
| `docs/` | Architectural documentation (NEW) |
| `.agents/` | Agent/organizational config |

Every first-party folder has a `structure.md` (the files, the public methods and
the child folders) and a `TODO.md` (the open work). Both are generated by
`scripts/generate_structure_docs.py`; run it with `--check` to verify that
they are up to date.

Not documented, because they are not ours to change: the vendored headers and
libraries under `src/ext/bridge/headers` and `src/ui/vendor`, the downloaded
tool under `ripgrep/`, the marketplace extensions under `src/ext/test_exts`,
and every build output (`build*`, `dist*`, `Vrutti_Release/`).

## Roadmap & Planned Architecture
The feature status of the workbench. "Dynamic" means the panels are created
and destroyed on demand instead of being fixed parts of the layout.

| Feature | Exists | Dynamic |
|---------|--------|---------|
| Problems / Diagnostics Panel | Yes | Yes |
| Split Editors | Yes | Yes |
| Search & Replace | Yes | Yes |
| Language Server Protocol | No | No |
| Diff Editor | No | No |
| Minimap & Breadcrumbs | No | No |

- **Dynamic Backgrounds**: an ultra-lightweight dynamic media renderer for the
  IDE background that aggressively unmounts and flushes its cache when an
  editor opens, so it costs nothing while you type.

## Cross-Cutting Concerns
- Security: eliminate `_popen`, `eval`, direct DOM `innerHTML` injection (see `problem.md`).
- Stability: fix terminal shutdown deadlock, IPC promise leaks, session memory leaks, `SettingsManager` blocking wait.
- Paths: zero hardcoding — resolve everything from executable directory.
