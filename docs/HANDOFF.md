This file is the prompt for the next session. Read it, then read the files it

## 1. The mission

Build **Vrutti IDE** — a native code editor — so that an extension which
works in the reference editor works in Vrutti, and so that the backend is
airtight.

Two standing priorities, in this order:

1. **Backend first.** A feature lands as a C++ plugin → an IPC method → a
   frontend component. No frontend work before the backend exists.
2. **Ship and publish.** Commit and push every coherent, verified increment.
   Do not leave the tree dirty at the end of a session.

### The hard requirement

> **If an extension works in the reference editor, it works in Vrutti.**

This is not a goal, it is a contract. It is why the extension host is a real
Node.js process running the real `vscode` API instead of a shim, and why a
missing feature is answered with a safe default instead of an error.

## 4. The architecture, in one paragraph

Three processes. The **frontend** is Lit + TypeScript + Vite, in
`src/ui/frontend`. The **extension host** is Node.js in `src/ext/exthost`,
running the real `vscode` API. The **core** is C++20 in `src/core`, built as
native plugins behind an `IPlugin` interface. The frontend and the extension
host talk to the core over a **private named pipe**, one per window
(`vrutti_pipe_<PID>`), with newline-delimited JSON. The wire format is called
*VruttiJSONBridge* and is **not** JSON-RPC 2.0.

> **Do not build a React-like C++ UI framework.** Lit + C++ `IPlugin` DLLs +
> the Node.js extension host is the decided design. Do not revisit it.

## 6. What to do next

The order is in `docs/BACKEND_HARDENING.md` and in `src/core/ipc/TODO.md`.
This is the queue:

### P0.3 — the shapes an ordinary extension touches

Work down this list. Each one is a shape of the upstream protocol.

| # | Shape | Why it matters |
|---|---|---|
| 1 | `MainThreadEditor` | The visible state of an editor: selections, visible ranges. |
| 2 | `MainThreadLanguages` | Diagnostics, tokenization, the language of a document. |
| 3 | `MainThreadLanguageFeatures` | The completion, hover and signature providers an extension registers. |
| 4 | `MainThreadTerminal` | Terminal creation and shell integration. |
| 5 | `MainThreadTask` | Task providers and execution. |
| 6 | `MainThreadQuickInput` | Input boxes and pickers. |
| 7 | `MainThreadNotification`, `MainThreadMessageService` | Progress and messages. |
| 8 | `MainThreadDebugService` | Debug adapters. |
| 9 | `MainThreadSearch` | File and text search providers. |
| 10 | `MainThreadWebview` | Webview panels and views. |
| 11 | `MainThreadConsole` | The output channel of an extension. |

`MainThreadFileSystem` and `MainThreadDocuments` are done. The shapes that
belong to features Vrutti does not have — chat, agents, embeddings, browsers,
authentication, notebooks — stay on the fallback answer. That is a documented
decision, not an oversight.

**How to implement one, every time:**

1. Read the shape in `../src/vr/workbench/api/common/extHost.protocol.ts`.
2. Implement the work in C++ — a service in `src/core/<area>/`.
3. Register the handler in `src/core/ipc/VSCodeProtocol.cpp`. Use
   `setAsyncHandler` when the handler has to answer later, for example when
   the call has to be forwarded to the extension host.
4. Write a test in `src/tests/integration/` that drives it over the real
   named pipe. Copy the shape of `ExthostFileSystemTest.cpp` and use the
   shared `ExtHostPipeClient.h`.
5. Update the audit numbers, the `TODO.md` files and `docs/BACKEND_HARDENING.md`.
6. Commit and push.

**The trap of the next shapes:** a shape that has a *mirror* on the host side
cannot be answered on the spot. `MainThreadDocuments` is the example: the host
resolves `workspace.openTextDocument()` only when the document is in its
mirror, so the delta has to reach the host *before* the call is answered. The
same holds for the editors and the languages: the host keeps a mirror of
every editor and every language, and the renderer has to feed it.

### The extensions

The installation of an extension is done by the core, in
`src/core/extensions/ExtensionService.cpp`:

```powershell
# the plugin ABI (src/core/plugins/ExtensionManager.cpp)
ExtensionManager.dll  ->  "list" | "listForUserInterface" | "install" | "uninstall" | "enable" | "disable"

# the protocol (the user interface -> the core)
extensions/install | extensions/uninstall | extensions/enable | extensions/disable
```

The rules the installer follows (no file may leave the folder of the
extension, no archive may expand without end, the manifest is checked before
anything is written, no shell is involved) are in
`docs/BACKEND_HARDENING.md`. The tests are `ExtensionInstallerTest` and
`ExtensionInstallProtocolTest`.

### Then the rest of the plan

| Phase | What |
|---|---|
| **P1** | Nothing may hang: drop the reply of a cancelled request, shut the terminal down without a deadlock, write the settings without blocking the caller. |
| **P2** | Nothing may crash: fuzz the JSON parser, reject a frame that lies about its length, drop a malformed frame and keep the connection. |

## 7. The contracts you must not break

### A missing feature is never an error

The extension host turns an error reply into a rejected promise. Most of the
calls that reach the host are not awaited, so the rejection becomes an
unhandled rejection, and the host reports the extension as errored. An
extension that uses a feature Vrutti does not have would look broken instead
of limited.

So: **no implementation → the benign default of the declared return type**
(`null`, `""`, `0`, `false`, `[]`). An error reply is correct only when a
handler exists and the operation genuinely failed, or when the peer broke the
protocol.

### The wire format

Newline-delimited JSON. Renderer → host:

```json
{"type":"init","data":{...}}
{"type":"request","reqId":1,"proxyId":52,"method":"$stat","args":[...]}
{"type":"reply","reqId":1,"res":...}
{"type":"replyErr","reqId":1,"err":{"$isError":true,...}}
{"type":"ack","reqId":1}
{"type":"cancel","reqId":1}
{"type":"terminate"}
```

Host → renderer: `{"type":"ready"}` and the same shapes.

The `data` of an `init` frame **must be an object**.

The control bytes are one byte long, which is what tells them apart from an
RPC frame — an RPC header is five bytes: a type byte and a big-endian
`uint32` request id.

### The details that bite

| Fact | Value |
|---|---|
| `MessageBuffer.readUInt32` / `writeUInt32` | **Big endian.** |
| `MessageIO.deserialize*` | Must be called on a buffer already advanced past the type and the request id. |
| `IConfigurationInitData` | `{defaults,policy,application,userLocal,userRemote,workspace,folders,configurationScopes}`. Every model is `{contents,keys,overrides}` — **not** `{}`. |
| `IWorkspaceData` | `{id,name,folders:[{uri,name,index}]}`. |
| `ExtensionIdentifier` | Must serialize as `{value,_lower}`. |
| `MainThreadWindow.$getInitialState` | Must return `{isFocused,isActive}`. |
| `MainThreadLanguageModelTools.$getTools` | Must return an **array** — `null` makes the host throw. |
| `product.ts` | Reads `globalThis._VSCODE_PRODUCT_JSON` and `_VSCODE_PACKAGE_JSON` as **objects**. |
| Proxy ids | `MainThreadFileSystem` is 52, `ExtHostFileSystem` is 100. The namespace is `proxy::Main::` and `proxy::Ext::`. |

### Binary payloads

| Direction | Form |
|---|---|
| Renderer → host | `{"$vsbuffer":"<base64>"}` — revived by `reviveVSBuffers`. |
| Host → renderer | The marshalled form `{"buffer":{"0":104,...}}`. |

`IPCClient::decodeVSBuffer` reads both. `IPCClient::encodeVSBuffer` writes the
marker form.

**The index of a byte is the key of the property, not the value.** The value
is the byte itself. Getting this backwards makes the size of the buffer
depend on the content of the file instead of on its length — a bug that was
in the code and is now fixed.

### The error names of the file system

They must match the upstream exactly, because the extension host maps
`err.name` to `FileSystemError.*`:

`FileNotFound`, `FileExists`, `FileNotADirectory`, `FileIsADirectory`,
`NoPermissions`, `Unavailable`.

`FileType`: `Unknown` 0, `File` 1, `Directory` 2, `SymbolicLink` 64.
`FilePermission`: `Readonly` 1, `Locked` 2, `Executable` 4.
`IStat`: `{type, mtime, ctime, size, permissions?}`, in milliseconds since the
Unix epoch.

## 9. The gotchas that cost time

| Gotcha | What to do instead |
|---|---|
| PowerShell 5.1 has no `&&`. | Use `;` and check `$LASTEXITCODE`, or separate the calls. |
| `Get-Content` returns strings, not lines. | Use `$_` inside the pipeline. |
| `Get-Content` without `-Encoding UTF8` mangles non-ASCII. | Read the bytes and decode as UTF-8 when the file has an em dash or a box character. |
| esbuild prints nothing when its output is a pipe. | Redirect to a file: `> out.log 2>&1`. |
| A `python -c "..."` with nested quotes will not parse in the shell scanner. | Write the script to a file and run it. |
| `Pattern.finditer(text, re.M)` passes `re.M` as the **position**, not the flags. | Compile the pattern with `re.M` instead. |
| `git add -A` has staged large build artifacts before. | Stage by name. `build-linux/_deps/imgui-src` is a dirty submodule pointer — never stage it. |
| `src/ext/bin/node.exe`, `src/ext/exthost/extensionHostProcess.mjs`, `*.mjs.map` and `src/ext/exthost/*.node` are gitignored. | They are build artifacts. Do not force them in. |
| `src/ext/package.json` is not a package manifest. | It is a large unrelated JSON blob. Leave it alone. |
| `src/ext/legacy/bootstrapper.js` is the old standalone host. | It is no longer in the pipeline. |
| The stale workspace path lives in the webview's `localStorage['lastWorkspace']`. | It is not in `settings.json`. `%APPDATA%\Vrutti\settings.json` holds theme and font settings only. |
| The `fs` namespace shadowing. | Inside `namespace vrutti::core`, the folder `fs` shadows a global alias. Use `stdfs` for `std::filesystem` in `VSCodeProtocol.cpp`. |
| A GUI app under gdb batch hangs. | Use targeted logging instead of a debugger for the UI. |
| `src/ext/test_exts/` holds real marketplace extensions. | The duplicate-id warning for `ms-python.python` is harmless. |

## 10. The shape of a good commit

Small, coherent, verified, and pushed. One feature per commit.

```powershell
git add <the files that belong to this change>
git commit -m "feat(ext-host): let an extension read and write files"
git push origin main
```

The message says what the change does, in plain words, and never names the
reference editor's vendor or product.

---

## 11. The rule of the day

> The extension host must never be surprised by the renderer.

Every answer is correct or benign. Every request has a deadline. Every frame
that arrives is either understood or dropped — never fatal. Every error has a
code from the central registry.

That is what "airtight" means here.
